# mod-procedural-dungeon

Procedurally generated dungeons: per-run unique layouts assembled at runtime
from existing WMO/M2 GameObjects on a client-known base map (default 37).
No client patch. See [README.md](./README.md) for install/usage and
`share-public/docs/World of Warcraft/procedural-dungeon/` for the full design
doc.

| `src/generator/PDv2WalkGrid.*` + `PDv2WorldMath.h` | **PDv2 walkable surface**: walk grid built from the kit's masks, A*, path simplification, the `PlanApproach` chase policy the creature AI runs on, and the world↔block/cell math in both directions (map 760 has no mmaps — this grid IS the navigation). Since **Round C / C1** `GridLineWalkable` is a true **supercover** test — an exact integer DDA over every cell the segment between the two cell centres enters, plus the **no-corner-cutting rule**: where the segment passes exactly through a cell corner, BOTH straddling cells must be walkable, because a creature has a body. Round B's Bresenham sampler skipped one cell at every minor-axis transition, which is how the patroller walked through walls; 2 136 of the 301 084 legacy-approved intra-mask pairs (0.71 %) really did cross a wall cell's interior, and the corner rule removes a further 7 468. Every consumer inherits it — `SimplifyGridPath`, `PlanApproach`, the AI's chase gate, the rejoin and the caster's `GridLineOkTo`. Pinned in the harness twice: `PD_SUPERCOVER_PAIRS_PIN` over every kit mask, and `CheckCornerRule`'s **eleven** hand-built cases, which are the only in-tree oracle for the corner half - three of them walk the same 45 degree corner BACKWARDS, because the rule reads `At(x + sx, y)` / `At(x, y + sy)` and every positive-delta case leaves the sign untested. Since **Round D / D1** the file carries a SECOND search beside the A\*, for patrols only: `FindPatrolPath(grid, from, to, propCells, out, PatrolCost{})` searches states of **(cell, incoming direction)** — five per cell, `none` belonging to the start alone — because a turn charge is a property of HOW a cell was entered and cannot be settled on the cell itself. Integer costs `step 10`, `turn 30`, `wallAdjacent 20` (any 4-neighbour of the ENTERED cell out of bounds or non-walkable — the grid edge is the void) and `propCell 60`, a Manhattan × `step` heuristic (admissible and consistent, which is what licenses the break at the goal cell) and a TOTAL order in the queue (`f` ascending, then state index), without which the route would be decided by the heap's shuffling of equal elements — precisely what differs between MSVC and libstdc++. `propCells` indexes like `grid.cells` (1 = a prop stands there), may be null, and is DROPPED rather than indexed when its size is not `grid.cells.size()`. A prop is a **cost, not a wall**: a beat must still exist when every lane cell carries one, or that patrol stands still all run. `MergeCollinear` keeps the endpoints and every turn — an interior point survives unless the incoming and outgoing deltas are collinear AND same-heading (`cross == 0 && dot > 0`), so it is idempotent and a beat that DOUBLES BACK keeps its turning point — and patrol legs are therefore axis-aligned, cell centre to cell centre, never diagonal. `FindGridPath` / `SimplifyGridPath` / `PlanApproach` are untouched and still carry the chase, where cutting a corner to reach a player is the point. Since **Round D / D2** the grid also carries the kit's **clearance layer**, `WalkGrid::patrolClear` (0..15 quarter-yards of free space at the cell's clear point, `PD_PATROL_QUARTER_YD` 0.25, 15 = free and also what an ABSENT layer reads as) plus `patrolDu`/`patrolDv`, the offset of that clear point off the cell centre. `PatrolInfoAt` is the single reader — a cell with no layer answers its own centre, which is what makes every pre-D2 kit and every hand grid behave exactly as before — and `PatrolPointToWorld` is what stands a creature on the clear point rather than the cell centre. `PatrolCost` charges the layer twice: `tightPerQuarter` (8) per quarter-yard MISSING from the entered cell, and `minClearQ` (4) below which the cell is BLOCKED outright — hence the **two-pass plan**, because a corridor whose every lane cell is tighter than `minClearQ` has no beat at all under the first pass and the caller replans with `minClearQ` 0, letting `tightPerQuarter` alone decide. `MergeClearPoints(grid, path, tolerance = PD_PATROL_MERGE_TOLERANCE_Q)` is the merge a beat now takes, and **no beat calls `MergeCollinear` directly any more**: it keeps `MergeCollinear`'s cell rule first and unconditionally (a turn is always a waypoint, so legs stay axis-aligned in cells, which is what licenses `MovePoint(generatePath = false)` on a map with no mmaps) and then asks the second question — would the leg the drop produces still pass every clear point it swallows within **2 quarter-yards = 0.5 yd**, perpendicular to that leg, re-testing the whole run on each drop. Integer arithmetic in 1/12-yard units (`cross² ≤ tol² · ab²`, the squared perpendicular against the squared leg length) because the waypoint count must be identical on MSVC and gcc. It is **NOT idempotent** and that is documented rather than fixed — a second pass sees only the survivors — so it is defined over the raw chain `FindPatrolPath` returns, which is the only thing any call site hands it. `MergeCollinear` stays exported as the statement of the cell rule alone and as the harness's oracle for the no-layer case. Harness: four hand grids for `FindPatrolPath` (the turn penalty beats an equal-length zigzag, the wall penalty keeps a 6×6 room crossing off the ring, a prop is walked around where there is a way and crossed where there is none), `CheckMergeCollinear`, and `CheckMergeClearPoints`' four cases run OUTSIDE the kit-mask guard so they hold on a box with no kit staged (a straight lane whose clear points all shift the same way still merges to two waypoints; one wobbling cell splits it into five with the four break distances written out by hand and `MergeCollinear` asserted at 2 on the same input, so the case compares against something; six paths merged both ways on a layer-free grid come out identical; and a bent path under alternating ±3 yd offsets keeps both turns, stays a subsequence in order and keeps every leg axis-aligned). Per merged leg the harness asserts both directions of the band — every covered cell's clear point passed within tolerance, re-derived in doubles from `PatrolInfoAt` rather than by reusing the engine's integer test, AND the walked line sampled every 0.5 yd end to end never leaving the band of cells the leg covers. The operator beats are pinned twice: `PD_OPERATOR_PATROL_PIN` = `1:10:24:1778:396;2:4:10:1002:190;3:2:8:754:152;4:6:8:250:62;5:6:16:1458:278;6:8:15:950:142;7:15:24:1282:296;8:6:8:250:62;9:7:16:1082:204;10:5:16:1154:204;11:10:16:482:124;12:6:14:1368:214;` over the twelve **corridor** beats (`k:waypoints:cells:cost:offsetSum`; the cost is the harness's own `PatrolCellPathCost` re-derivation, since `FindPatrolPath` reports none), and `PD_OPERATOR_PATROL_PIN_NOLAYER` for a kit with no clearance layer, which must stay unchanged because the two merges are then the same function. Only the layered string moved in D2's follow-up: `cells`, `cost` and `offsetSum` are read off the RAW chain that no merge touches, so the route is the same route said in more points (30 waypoints → 85; corridor 7's 24 cells went from one straight line to fifteen waypoints, corridor 3 did not move at all) |

## Conventions

- Reserved IDs: GO 910000–910099, NPC 910500–910549 (registered in
  share-public `06-custom-ids.md`)
- Determinism: never use std `<random>` distributions in `src/generator/`
  (implementation-defined) — only `PDRandom` helpers; keep iteration orders
  fixed. Same seed must yield the same dungeon on gcc/clang/MSVC.
- Both harnesses must stay green: `pdgen --batch 500` and `pdblock --batch 500`
  = 0 failures.
- The block planner's manifest is a **contract with two other implementations**:
  `scripts/49_pd_compose_blocks.py` in the ForgottenLand2.0 workspace (the
  byte-exact oracle for the client composer) and the `FLPD2` parser in
  `fl-stream-client`. After changing `EmitManifest`, feed a real manifest
  through the oracle — `pdblock --manifest <seed> <file>` then
  `python 49_pd_compose_blocks.py --manifest <file>` — or the three will drift.
- AC code style, `-Werror`-clean; run `apps/codestyle/codestyle-cpp.py` from
  the module root before committing.
